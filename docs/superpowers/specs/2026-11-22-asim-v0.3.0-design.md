# ASIM v0.3.0 设计：多协议节点 + WebUI 可配置

日期：2026-11-22

## 目标

1. `asim-relay` 支持 `trojan` / `vless` / `hysteria2` 三种节点协议。
2. WebUI 可选择/修改路由器地址，默认取手机默认网关。
3. 节点配置在 WebUI 中读写，无需 SSH 改 `relay.json`。
4. WebUI 显示 relay 运行状态、运行时间、丢包，并能测节点延迟。
5. Release 同时提供 Linux amd64 与 Windows amd64 的 relay 二进制，模块版本 v0.3.0。

## 关键实测结论（决定实现方式）

- 现有生产节点（trojan）从路由器可达；手写 trojan UDP 帧验证通过。
- 订阅里的 VLESS 节点都配置了 `flow: xtls-rprx-vision`（部分叠加 xhttp/reality）。
  Xray 服务端对「空 flow + 裸 UDP」直接断连；官方客户端走的是 **Vision + Mux + XUDP**。
- 用官方 Xray 25.12.8 从路由器实测：VLESS(vision, TLS/TCP) 经 UDP 到 8.8.8.8:53 成功（212ms）。
- 结论：VLESS 必须用 Xray 引擎，手写只能覆盖不含 vision 的极少数节点，不做。
- Hysteria2 用官方 `github.com/apernet/hysteria/core/v2` 客户端库（QUIC 无法手写）。

## 方案

- **VLESS**：内嵌 `github.com/xtls/xray-core`（pin `v1.251208.0`，该版本仍支持
  `allowInsecure`；更新的版本移除了它，需要证书 pin，暂不跟）。在进程内起一个
  `127.0.0.1:随机端口` 的 SOCKS 入站，relay 自己实现 SOCKS5 UDP ASSOCIATE，
  把 IKE/ESP 包交给 Xray 的 VLESS 出站。支持 `tcp/ws/grpc/httpupgrade/xhttp`、
  TLS/REALITY、vision flow。
- **Hysteria2**：官方 core 客户端，一个节点一个 QUIC 客户端，每个流一个 `UDP()` 会话。
- **Trojan**：保留现有手写实现。
- 节点结构扩展：`protocol`、`insecure`、`flow`、`network`、`path`、`host_header`、
  `service_name`、`reality_public_key`、`reality_short_id`、`fingerprint`、`encryption`。
  旧配置没有 `protocol` 时按 trojan 处理；trojan 的 `insecure` 缺省保持 true（兼容现状）。
- **relay API** 新增（全部带 `X-ASIM-Token`）：
  - `GET /config` 读取配置；
  - `PUT /config` 热更新 `node`/`domain`/`enabled`，监听地址变更返回 `restart_required`；
  - `POST /ping` 用当前或传入的节点做一次真实 UDP 往返（DNS 查询），返回毫秒数。
  - `/status` 增加 `protocol`、`version`。
- **UI**：
  - 路由器地址卡片：默认网关、可改可存（写入 `asim.conf` 的 `ROUTER_API`）；
  - 节点配置卡片：协议/地址/端口/密码或 UUID/SNI/跳过证书校验，高级项折叠；
  - 延迟测试按钮；
  - 状态区显示协议、运行时间、丢包、ePDG 地址数、活跃流。
- **PC 部署**：`listen_addr` 支持 `0.0.0.0`，Release 出 Windows/Linux amd64；UI 的路由器
  地址默认仍取手机网关，PC 用户填 PC 的 LAN IP。
- **版本**：`module.prop` → `v0.3.0`，`build.ps1` 同时编译两个平台的 relay。

## 非目标

- 不做 Hysteria2 的 obfs/端口跳跃；不做 VLESS 的 gRPC multi-mode 等冷门参数细节。
- 不代理 ePDG 以外的流量；不改手机侧防驻网逻辑。
- 不为 Xray 升级到移除 `allowInsecure` 的版本；升级时需改为证书 pin。

## 风险

- 内嵌 Xray 让 relay 二进制约 35MB（原 ~9MB）；路由器 x86_64 可接受。
- Hysteria2 依赖 UDP/QUIC，部分网络会被墙；实测不通时属网络问题，不是代码问题。
- 节点凭据经手机 WebUI 传给路由器 API，和现有 token 同等级信任。

## 验收

1. `go test ./...` 通过（节点校验、Xray 配置映射、SOCKS5 UDP、trojan 帧）。
2. 本机跑 Windows 二进制：`/status`、`GET/PUT /config`、`/ping` 对真实 VLESS 节点成功。
3. 路由器部署后：生产 trojan 节点仍可建立 flow；`/ping` 正常；WebUI 可读写节点。
4. 手机 `asimd.sh selftest`、`nocamp.sh selftest` 通过；模块 zip 可安装。
5. WebUI 用 mock `ksu` 在浏览器里目检通过。
